# 要件定義書

## 1. システム概要

### 1.1 システム名

宅配注文管理システム

### 1.2 システムの目的

飲食店の商品をオンラインで注文し、指定した住所まで配達してもらうためのシステムを構築する。

### 1.3 対象ユーザー

- 利用者
- 店舗スタッフ
- 配達員

## 2. システムスコープ

### 2.1 対象範囲

本システムでは、以下の業務を対象とする。

1. ユーザー登録・認証
2. 店舗・商品検索
3. カート管理
4. 注文作成
5. 店舗側の注文受付・調理管理
6. 配達員による配送管理
7. 注文履歴管理

### 2.2 対象外

以下はMVPでは対象外とする。

- 実際のクレジットカード決済
- 外部決済サービスとの連携
- 地図APIによるリアルタイム経路検索
- リアルタイム位置情報共有
- 複雑なクーポン・ポイント機能

決済はモックとして実装する。

## 3. システム利用者

| 利用者 | 主な責務 |
|---|---|
| 利用者 | 商品を検索し、カートから注文する |
| 店舗スタッフ | 商品を管理し、注文を受け付けて調理する |
| 配達員 | 注文を受け取り、商品を配達する |

## 4. 基本業務フロー

利用者
→ 店舗を検索
→ 商品を確認
→ カートに追加
→ 注文を確定
→ 店舗スタッフが注文を受付
→ 調理
→ 調理完了
→ 配達員が商品を受け取る
→ 配達
→ 配達完了

## 5. 注文の考え方

1回の注文確定で複数店舗の商品を購入できる。

そのため、購入単位を `OrderGroup`、店舗ごとの注文単位を `Order` として分離する。

例：

```text
1回の注文確定
    ↓
OrderGroup
    ├── Order（店舗A）
    └── Order（店舗B）
```

## 6. 注文ステータス

```text
注文受付
  ↓
調理中
  ↓
調理完了
  ↓
配達中
  ↓
配達完了
```

キャンセル：

```text
注文受付 → キャンセル
```

## 7. 非機能要件

### 7.1 セキュリティ

- パスワードは平文で保存しない。
- パスワードはハッシュ化して保存する。
- ロールに応じてAPIへのアクセスを制御する。
- 認証にはJWTを使用する。

### 7.2 保守性

- Controller / Service / Mapperの責務を分離する。
- 業務ロジックをControllerに集中させない。
- APIのエラー形式を統一する。
- Gitで変更履歴を管理する。

### 7.3 テスト

主要な業務ロジックについてJUnit 5およびMockitoを使用して単体テストを実施する。

## 8. 前提・制約

- DBMSはMySQLを使用する。
- バックエンドはJava 21 / Spring Boot 3を使用する。
- ORMではなくMyBatisを使用する。
- 決済はモック実装とする。
- MVPでは配送エリアを簡易的に扱う。
